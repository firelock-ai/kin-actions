# kin-actions

Shared GitHub Actions reusable workflows for the Kin registry release pipeline.

## Contents

- `cargo-release-train.yml` — coalesces trusted `main` drift into one exact generated Cargo release PR.
- `cargo-registry-release.yml` — validates, publishes, fresh-consumer checks, tags, and dispatches an admitted Cargo release.
- `cargo-dependency-wave.yml` — coalesces registry releases into signed dependency-update PRs in consumer repos.
- `self-release-train.yml` — prepares the next `kin-actions` version PR from durable repository state.
- `release.yml` — publishes the exact tested `kin-actions` tag and GitHub Release.
- `pin-wave.yml` — globally inventories every live consumer, then applies strict protection and proof gates to the one-repo pilot and each bottom-up stage through a separately scoped App.
- `public-history-hygiene.yml` — validates public metadata without rewriting history.

## Boundary rule

Put work here when it changes shared CI behavior across repos. Version strictly:
any breaking change to the workflow interface requires a semver bump and a
consumer pin-wave across all repos that reference a `@vX.Y.Z` tag.

## Version cadence

- Consumers pin to `@vX.Y.Z` refs.
- Ordinary feature PRs do not edit Cargo package versions or this repository's
  `VERSION`; the automatic trains own those generated bytes.
- Release intent is carried only by an immutable
  `Kin-Release-Intent: minor|major` trailer on a landed first-parent commit;
  the highest trailer since the last release wins and absence means patch.
  Mutable `release:*` labels are descriptive/authentication metadata only and
  have zero automatic release-intent authority.
- Protected generated PRs merge only after the repository's normal required
  checks. Publication then performs a registry-only consumer check before
  immutable tag creation and downstream delivery.
- Rollback is forward-only: fix and publish a newer version (or yank a bad Cargo
  release) and repin. Never move or reuse a published version or tag.
